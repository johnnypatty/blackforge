# BlackForge 0.3.0

BlackForge 0.3 turns the original BlackArch catalog navigator into a
source-aware Arch Linux security-tool manager while keeping package changes
reviewable and delegated to pacman.

## What is new

- Full-screen searchable terminal UI.
- Exact install/remove/upgrade plans with pacman metadata when available.
- Transaction history, conservative state-checked undo, bounded automatic
  retries, and manual resume.
- HTTPS BlackArch mirror listing, testing, recommendation, backup, and atomic
  selection.
- On-demand catalog change reports.
- Checksum-verified self-update for user installations created by `install.sh`.
- Source-qualified environment export/import with plan-first reproduction.
- Nine curated tools from official Arch repositories, including `nmap`,
  `masscan`, `aircrack-ng`, `hashcat`, `john`, `sqlmap`, `tcpdump`, and
  Wireshark.
- Seven reviewed mixed-source tool collections.
- Two maintenance views across all 2,861 BlackArch catalog entries:
  **Recently maintained** and **Needs attention**.
- Clear nested help, JSON planning, consistent non-mutating dry runs, and a
  complete command reference.
- A redesigned README with installation, workflows, evidence boundaries,
  troubleshooting, and the trust model.

## Security and correctness fixes

- Package operands are validated and separated from pacman options.
- Repository setup fails closed on checksum drift unless one exact reviewed
  SHA-256 is approved.
- Cross-host/non-HTTPS download redirects are rejected.
- Self-update rejects unsafe/duplicate asset names and ambiguous checksums.
- Environment/history/resume records cannot disguise an official Arch package
  as a BlackArch package.
- Undo refuses partial rollbacks and packages changed after the recorded
  transaction.
- State writes are atomic, bounded, and serialized across processes.
- Mirror changes require literal approval, preserve `SigLevel`, reject
  symlinks, and avoid no-op rewrites.
- Real pacman output is both streamed and retained, so bounded retries can
  classify actual download/network failures without hiding interactive output.
- Resumed operations create history records, and concurrent transaction state
  changes cannot overwrite one another.
- Release publication separates read-only build/test from the write-enabled
  publish step, pins Action commits, binds tag and package versions, and
  exhaustively checks the native source archive.
- Self-update accepts only the exact BlackForge wheel and verifies the installed
  version; installation scripts reject unsafe relative or symlinked roots.

## Evidence snapshot

- BlackArch website entries: **2,861**
- Present in the refreshed x86-64 repository check: **2,858**
- Website-listed but absent from that repository snapshot: **3** (`rtl`, `sr`,
  `vega`)
- Maintenance evidence: **780 current**, **680 stale**, **143 archived**,
  **1,258 unknown**

Repository presence and maintenance activity are evidence signals, not proof
that every program or code path works. BlackForge does not launch the catalog
tools during its full-catalog audit.

## Start here

```bash
git clone https://github.com/johnnypatty/blackforge.git
cd blackforge
bash install.sh

blackforge help install
blackforge search nmap --source arch
blackforge --dry-run install arch:extra/nmap
```

See the [README](https://github.com/johnnypatty/blackforge#readme),
[complete command reference](https://github.com/johnnypatty/blackforge/blob/v0.3.0/docs/COMMANDS.md),
and [changelog](https://github.com/johnnypatty/blackforge/blob/v0.3.0/CHANGELOG.md)
for details.
