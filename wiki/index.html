01

Installation

BlackForge targets Arch Linux and derivatives with pacman. Python 3.10 or newer is required.

git clone https://github.com/johnnypatty/blackforge cd blackforge bash install.sh

The user installer creates an isolated environment under ~/.local/share/blackforge, links the command into ~/.local/bin, and installs shell completions. It refuses unrelated or symbolic-link install targets.

The project is unofficial and is not affiliated with BlackArch Linux. Read install.sh before running it.

Native Arch package

Release assets also include source for the maintained PKGBUILD in packaging/arch.

02

First run

blackforge doctor blackforge search "network mapper" blackforge --dry-run install amass blackforge setup

setup downloads the official BlackArch strap script, verifies the upstream SHA-1 and a displayed SHA-256, and asks for review. Official Arch tools such as arch:extra/nmap do not require BlackArch setup.

03

Command reference

Run blackforge help COMMAND for every option and examples, or blackforge help --all for the complete manual.

CommandWhat it does
search / show / listBrowse BlackArch and curated official Arch catalog metadata.
plan install|remove|upgradeResolve dependencies, sizes, conflicts, and exact pacman arguments without changes.
install / remove / upgradeConfirm and run a validated pacman transaction, then record history.
status --all --remoteCompare the bundled catalog against the official BlackArch repository database.
maintenance summary|listSeparate recently maintained evidence from stale, archived, and unknown evidence.
collection / communityPlan or install built-in and reviewed community package sets.
env export|importReproduce recognized security-tool environments with drift review.
completion bash|zsh|fishGenerate shell completion scripts.
help --lang trShow the Turkish quick-start guide.

04

Audit, locks & SBOMs

sudo pacman -S arch-audit # optional official advisory helper blackforge audit --output audit.json blackforge lock create lab.lock.json nmap amass blackforge lock compare lab.lock.json blackforge lock sbom lab.lock.json lab.cdx.json --format cyclonedx

audit keeps four ideas separate: an update is available, a published advisory affects the version, a package disappeared from configured repositories, or an upstream project lacks recent maintenance evidence. They are related but not interchangeable.

Locks include exact installed versions, trusted source/repository, and SHA-256 when the exact package archive still exists in pacman's local cache. A missing archive checksum is recorded as null, never invented.

05

Snapshots & rollback

blackforge snapshot status blackforge snapshot create --description "Before lab refresh" blackforge snapshot create --description "Before lab refresh" --apply blackforge install --snapshot amass blackforge snapshot rollback-plan lab.lock.json

Snapshot creation is plan-only unless --apply is present. Transaction snapshots require a Btrfs root and a configured Snapper profile named root. Rollback planning only locates exact archives and prints the pacman command; it does not execute a downgrade.

06

Community presets

Presets are public, reviewable JSON—not installer scripts. Published presets can contain only an ID, description, GitHub authors, tags, license, review state, and source-qualified package references.

blackforge community list blackforge community show network-observation blackforge community apply network-observation # plan blackforge community apply network-observation --apply blackforge community validate my-preset.json

Share yours

  1. Copy a JSON file from community/presets/.
  2. Set a unique ID and your GitHub handle.
  3. Use blackarch:NAME or arch:REPO/NAME.
  4. Leave reviewed false.
  5. Run python scripts/validate_community.py and open a pull request.

07

AUR metadata

blackforge aur --enable-aur search zaproxy blackforge aur --enable-aur info zaproxy

The command queries the official AUR RPC for metadata such as maintainer, age, votes, popularity, and out-of-date state. AUR content is user-submitted and unsupported. BlackForge deliberately has no AUR install command and never downloads, reviews, builds, or executes a PKGBUILD.

08

Dashboard & Linux integration

blackforge dashboard build report.html --record blackforge integration systemd ~/.config/systemd/user systemctl --user enable --now blackforge-update.timer blackforge --json integration packagekit man blackforge

The HTML report is portable and contains no JavaScript. The generated systemd timer is disabled until you review and explicitly enable it; it checks catalog changes weekly. PackageKit output uses compatible package IDs and state names, but BlackForge does not claim to be a PackageKit backend.

09

Safety model

  • Package references are strictly validated and resolved against bundled trusted catalogs.
  • Mutating operations show a plan and require confirmation unless you deliberately pass -y.
  • Pacman handles official repository signatures and dependency resolution.
  • Community data cannot contain commands, URLs, hooks, or unknown packages.
  • Remote endpoints are fixed HTTPS origins with bounded responses and timeouts.
  • Maintenance evidence is never presented as proof that a tool runs correctly.
Use security tools only on systems you own or where you have explicit permission. BlackForge organizes packages; it does not grant authorization.

Troubleshooting

Command not found

export PATH="$HOME/.local/bin:$PATH" blackforge --version

BlackArch package unavailable

blackforge repo status blackforge setup sudo pacman -Syy

Get a diagnostic snapshot

blackforge doctor blackforge --json audit blackforge --json snapshot status

Open an issue without credentials, private hostnames, or target data.
